# TheNodes v0.3.0

Released 2026-09-05.

## Summary

This pre-1.0 release adds UDP/Noise transport, NAT traversal and connection
policy, framework delivery semantics, and connection lifecycle monitoring.

## Highlights

- Optional Noise-secured UDP sessions with config-driven capability
  advertisement and NAT traversal support.
- Framework-owned fire-and-forget, reliable, and ordered-reliable delivery
  semantics.
- Route health monitoring, heartbeat-based liveness, and automatic reconnect
  policy.
- Async plugin message handling and extension-kind subscriptions.

## Breaking changes and migration

- Rust 1.83 or newer is required.
- Plugins must implement async `on_message` and be rebuilt for plugin ABI 2.
- Construct `PluginContext` with `PluginContext::new`.
- Manual `NetworkConfig` construction must include the new optional transport,
  connection policy, NAT traversal, and delivery fields.
- `make_secure_channel` returns a `Result`; callers must handle configuration
  errors.
- Noise requires `--features noise`. Selecting Noise without that feature now
  rejects the connection instead of using plaintext.
- `HELLO` and delivery metadata have changed. Mixed-version deployments have
  not been qualified; use a coordinated upgrade.

## Compatibility

- Minimum supported Rust version: 1.83.
- Plugin ABI: 2. Plugins compiled against an earlier ABI must be rebuilt.
- The locked dependency graph is tested with default and all features on Rust
  1.83.
- UDP Noise transport requires the optional `noise` Cargo feature.

## Known limitations

- CA chain analysis is heuristic; complete cryptographic path validation
  remains pending.
- Certificate date extraction is a placeholder; validity flags do not yet
  enforce certificate dates.
- CRL/OCSP enforcement and Noise static-key trust policy remain pending.
- Hole punching is best-effort and some networks require relay fallback.
- Framework delivery acknowledgements are not application persistence or read
  receipts.
- Plugin persistence and end-to-end application encryption remain application
  responsibilities.
