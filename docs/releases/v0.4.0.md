# TheNodes v0.4.0

Released 2026-09-07.

## Summary

This pre-1.0 release unifies TLS and Noise trust decisions, adds optional UPnP
port mapping and NAT diagnostics, gives plugins isolated durable data
directories, and makes relay payload framing explicit.

## Highlights

- Shared fingerprint trust semantics for TLS SPKI and Noise static keys,
  including allowlists, exact pins, observe mode, and fail-closed TOFU.
- Cryptographic WebPKI path and certificate-validity enforcement for TLS.
- Optional UPnP-IGD TCP mapping with lease renewal and conservative NAT
  diagnostics.
- Stable plugin identities and plugin-scoped data directories.
- Explicit base64 framing for opaque relay payloads, preserved through retries
  and store-and-forward.

## Breaking Changes and Migration

### Plugin ABI 3

All plugins must be rebuilt against TheNodes 0.4.0 and provide a stable,
unique plugin ID:

```rust
fn plugin_id(&self) -> &'static str {
    "my-plugin"
}
```

Pin dynamic plugin dependencies to the host release:

```toml
thenodes = "=0.4.0"
```

Plugin IDs may contain ASCII letters, numbers, `.`, `-`, and `_`. Existing
plugins that need durable state should obtain their assigned directory through
`PluginContext::plugin_data_dir()`.

### Relay Wire Format

`RELAY_FWD` now stores opaque application bytes in
`msg_type.RELAY_FWD.opaque_payload_b64`. The outer `Message.payload` must be
`null`. Upgrade all relay participants together; mixed 0.3.x and 0.4.x relay
paths are unsupported.

## Compatibility

- Minimum supported Rust version: 1.83.
- Plugin ABI: 3.
- Default Cargo features remain empty.
- Noise requires the optional `noise` feature.
- UPnP requires the optional `upnp` feature and explicit runtime activation
  under `[network.nat]`.

## Known Limitations

- CRL and OCSP loading and enforcement are not implemented.
- UPnP support is limited to IGD; PCP and NAT-PMP are not implemented.
- NAT classifications are diagnostics, not guarantees of router behavior.
- UDP hole punching remains best-effort and some networks require relay
  fallback.
- Plugin code runs in process without sandboxing and must be treated as trusted.
